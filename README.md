# 国库 · DEBATE VAULT

> 为辩论选手打造的论据资料库：多人共建、实时同步，检索、核验、备战，一键导出 Word 备战稿。

![HTML](https://img.shields.io/badge/frontend-single%20file%20HTML-e34c26) ![JavaScript](https://img.shields.io/badge/JavaScript-vanilla-f7df1e) ![Supabase](https://img.shields.io/badge/backend-Supabase-3ecf8e) ![Realtime](https://img.shields.io/badge/sync-Realtime-blue) ![RLS](https://img.shields.io/badge/security-RLS%20%2B%20RPC-purple)

**国库**是一个面向辩论队的论据管理应用。资料按「数据标题」分组，每条论据带有领域、形式、日期、来源与出处凭证，支持版本历史、真实性上诉与官方核验。贡献者把论据放进「备战夹」，即可按固定版式导出为 Word 文档。

前端是单个 `index.html`（原生 JavaScript，无构建、无框架），后端是 [Supabase](https://supabase.com)（PostgreSQL + Auth + Realtime）。所有权限都由数据库强制执行，不依赖前端。

## 功能亮点

| 模块 | 说明 |
|---|---|
| 📚 **数据大厅** | 按数据标题分组的可折叠列表；22 个核心领域、10 种资料形式的侧栏筛选；全文搜索（含模糊匹配与关键词高亮）；组内按录入时间、论据日期或点赞数排序 |
| 👤 **账号系统** | 注册用「用户名 + 邮箱 + 密码」，登录用「邮箱 + 密码」；用户名全站唯一（不分大小写）；可在设置中修改用户名 |
| 🎒 **备战夹** | 为每场比赛建立备战辩题，从大厅一键收藏数据标题，再逐条勾选论据；只引用不复制，**全体贡献者共用同一份并实时同步** |
| 📄 **Word 导出** | 按固定表格版式（数据标题 / 出處 / 內容 / 參考）导出备战夹，网址自动生成超链接，出处后附日期 |
| 📅 **论据日期** | 年份必填，月份与日期选填，显示、排序、导出均按实际精度处理，数据库校验日期真实存在 |
| 🛠️ **管理后台** | 管理员查看全部用户、调整身份、限制账户，生成与作废授权密钥，查看操作日志 |
| ⚖️ **上诉仲裁** | 对存疑论据发起上诉，管理员仲裁；同一资料 24 小时内上诉与撤回各限 3 次，**由数据库计算，无法绕过** |
| 🕰️ **版本历史** | 每次修正生成新版本，旧版本不可删除，时间轴可查 |
| ✅ **官方核验与下架** | 管理员可标记「官方已核实」，也可下架资料（普通用户不可见） |
| 🔄 **实时同步** | 任何人的改动（资料、投票、上诉、备战夹）几百毫秒内推送给所有在线用户 |
| 🎨 **外观** | 明暗模式、6 套低饱和配色、6 种强调色、减少动效选项 |
| ♿ **可访问性与响应式** | 键盘可达、`aria` 状态标注、弹窗焦点管理、尊重 `prefers-reduced-motion`；900px 以下侧栏转抽屉，适配刘海屏 |

## 系统架构

```
┌──────────────────────────┐        HTTPS         ┌─────────────────────────────────┐
│  浏览器 / 静态托管         │ ───────────────────► │  Supabase                        │
│  index.html（单文件）      │                      │                                 │
│  · 界面与交互              │  Auth（邮箱+密码）    │  Auth        用户与会话           │
│  · 内嵌 VaultAPI 连接层    │  REST / RPC          │  PostgreSQL  表 + RLS + 函数      │
│  · Word 导出（浏览器内生成）│ ◄─────────────────── │  Realtime    变更推送             │
└──────────────────────────┘     实时变更推送       └─────────────────────────────────┘
```

- **读**：前端通过 Supabase 客户端直接读取，受行级安全（RLS）约束；游客可浏览资料。
- **写**：资料、投票、上诉、仲裁、用户管理等一律经数据库函数（RPC），函数内逐个校验身份；前端无法直接写这些表。
- **备战夹**：贡献者及以上可直接读写 `motions` / `motion_items`，由 RLS 限制。
- **偏好设置**（明暗模式、配色等）只保存在本浏览器的 LocalStorage，不进数据库。

## 快速开始

### 前置条件

- 一个 [Supabase](https://supabase.com) 项目（免费版即可起步）
- 任意静态托管（GitHub Pages、Vercel、Netlify 等），或直接用浏览器打开 `index.html`

### 1. 初始化数据库

1. 在 Supabase 后台打开 **SQL Editor → New query**。
2. 粘贴 `schema.sql` 的全部内容并点击 **Run**。脚本可重复运行，也能给已有的旧库补上新列。

### 2. 填写连接信息

打开 `index.html`，找到文件中的 `window.VAULT_CONFIG`：

```js
window.VAULT_CONFIG = {
  url: 'https://你的项目ID.supabase.co',
  anonKey: '你的 anon / publishable key'
};
```

两个值都在 Supabase 后台 **Project Settings → API**。

> ⚠️ 只能填 **anon / publishable key**。**绝对不要**把 `service_role` / secret key 放进网页或提交到仓库。anon key 本身可以公开，数据安全由数据库的 RLS 与函数保证。

### 3. 配置登录

在 **Authentication** 中：

- **Providers → Email**：启用邮箱登录。
- **Confirm email**：决定注册后是否需要先点邮件确认。开启后，用户注册完要先去邮箱确认，再回来登录。
- **URL Configuration**：把你的网站地址加入 Site URL / Redirect URLs。

### 4. 设置第一位管理员

新注册的用户都是「普通会员」，而生成授权密钥需要管理员身份，所以**第一位管理员要手动指定**：

1. 先在网页上用你的邮箱注册一个账号。
2. 在 SQL Editor 执行（把邮箱换成你的）：

```sql
update public.profiles set role = 'admin'
where id = (select id from auth.users where email = 'you@example.com');
```

3. 刷新网页，右上角会出现「管理后台」。之后的提权都可以在后台完成。

### 5. 部署

**本地预览**：直接用浏览器打开 `index.html`。

**GitHub Pages**：

1. 将 `index.html` 与 `schema.sql` 推送到仓库。
2. **Settings → Pages**，Source 选择 `main` 分支根目录。
3. 访问 `https://<user>.github.io/<repo>/`。

> 如果页面提示「网站还没有连接数据库」，说明 `VAULT_CONFIG` 还没填好，或 Supabase 脚本未能加载。

> 快捷键：`/` 聚焦搜索，`Esc` 关闭弹窗、菜单或侧栏。

## 权限体系

| 角色 | 权限 |
|---|---|
| 游客 | 检索、浏览资料 |
| 普通会员 | 游客权限 + 点赞 / 点踩、修改自己的用户名 |
| 授权贡献者 | 会员权限 + 录入新资料、修正历史资料、发起与回撤上诉、**使用备战夹与导出 Word** |
| 官方管理员 | 贡献者权限 + 官方核验、下架、上诉仲裁、**管理后台** |
| 已限制 | 被管理员限制的账户：仍可浏览，但不能点赞、录入、上诉或使用备战夹 |

**提权方式**：用户在「设置 → 切换模式」输入管理员生成的授权密钥。用户也可以随时主动降级，无需密钥。

## 管理后台

仅管理员可见，入口在顶栏。所有操作由数据库校验并写入操作日志。

- **用户**：查看全部注册用户的用户名、邮箱、身份、状态、录入数、注册与最近登录时间；顶部统计注册用户、贡献者、管理员与被限制人数；可调整身份、限制或解除限制账户。管理员不能修改或限制自己，避免把自己锁在外面。
- **授权密钥**：生成带备注、可限次数、可设有效天数的密钥，授予「贡献者」或「管理员」身份。密钥明文**只在生成时显示一次**，数据库只存哈希；可随时作废。密钥输入错误过多会被临时锁定（15 分钟内失败 5 次）。
- **操作日志**：记录调整身份、限制账户、生成与作废密钥、导入资料、核验与上下架等操作。
- **上诉仲裁中心**：单独的页面。「通过上诉」会永久清除该资料，「驳回上诉」清空上诉记录，所有裁决写入仲裁记录。
- **数据管理**（设置页）：导出全部资料、仲裁记录与备战夹为 JSON；也可把旧版导出的 JSON 追加导入云端（不会覆盖现有资料）。

## 备战夹

备战夹相当于「按比赛分类的收藏夹」，仅授权贡献者及以上可用，**所有贡献者共用同一份，变更实时同步**。

1. **选定战场**：在备战夹页面新建备战辩题（可同时备战多个），可随时「结束备战」或「恢复备战」。
2. **大厅收藏**：每个数据标题右侧有「备战」按钮。
   - 只有一个备战中的辩题：点击加入，再点一次取消，页面不跳转。
   - 有两个及以上：弹出多选框，可同时加入多个备战夹，取消勾选即移除。
3. **精选论据**：回到备战夹页面，勾选每个数据标题下要用的论据，点击「保存修改」生效；未保存的修改会有标记，可「放弃修改」。

设计原则：备战夹只保存对资料的**引用**，不会修改数据大厅或数据库中的原始资料；已下架的论据不会出现在备战夹，也不会被导出。

## Word 导出

在备战夹中选中辩题，点击「导出 Word」，生成 `备战夹_辩题名.docx`。

**版式**

- 每个数据标题一张单列带边框表格，首行居中加粗 18 磅显示标题。
- 每条论据一行，依次为：
  - `出處：来源名（日期）`，加粗；日期随填写精度显示为「2024 年」「2024 年 3 月」或「2024 年 3 月 5 日」
  - 论据内容，圆点列表
  - `參考：` 后接可点击的网址超链接；文献文件则写明文件名
- 纸张为 Letter，页边距 2.54 厘米。

导出在浏览器内完成：内置最小化的 `.docx` 与 ZIP 生成器，**不依赖任何第三方库**。

## 数据库设计

主要数据表：

| 表 | 用途 |
|---|---|
| `profiles` | 用户资料：用户名（唯一）、身份、是否被限制 |
| `entries` | 论据：标题、内容、领域、形式、年/月/日、来源、出处凭证、核验与下架状态、上诉计数 |
| `entry_versions` | 论据的版本历史（只增不删） |
| `votes` | 点赞 / 点踩（每人每条一票，按用户 id 记录） |
| `appeals` / `appeal_log` | 上诉记录；以及用于 24 小时熔断计算的流水（前端不可读） |
| `court_log` | 仲裁记录 |
| `motions` / `motion_items` | 备战夹：备战辩题，以及每个辩题下各数据标题选中的论据 id |
| `access_keys` / `key_attempts` | 授权密钥（仅存哈希）与失败尝试记录 |
| `admin_log` | 管理员操作日志 |

主要数据库函数（RPC）：`add_entry`、`edit_entry`、`cast_vote`、`file_appeal`、`withdraw_appeal`、`redeem_key`、`lower_my_role`、`update_my_name`，以及管理员专用的 `admin_set_role`、`admin_set_banned`、`admin_create_key`、`admin_revoke_key`、`admin_list_users`、`court_pass`、`court_reject`、`admin_import_entries` 等。

**Realtime**：`entries`、`entry_versions`、`votes`、`appeals`、`motions`、`motion_items`、`profiles`、`court_log` 已加入实时发布。

## 安全设计

- **权限在数据库，不在前端**：身份存于 `profiles`，由 RLS 与函数内的 `require_role()` 强制执行；前端按钮只是外观。
- **前端无法直接写关键表**：资料、投票、上诉、密钥、日志等表对游客与登录用户均撤销了写权限，只能通过函数。
- **认证**：使用 Supabase Auth（邮箱 + 密码），密码不经过你的代码，不存本地。
- **密钥只存哈希**：授权密钥明文仅在生成时显示一次；兑换有失败次数限制。
- **熔断在服务端**：上诉与撤回的 24 小时限制由数据库计算，清缓存、换浏览器都绕不过去。
- **版本不可删**：修正只会新增版本。
- **已下架资料**仅管理员可见。

## 已知限制

- **单次读取上限**：前端一次性读取全部资料。Supabase 默认单次最多返回 1000 行，资料超过这个量后需要改为分页读取。
- **没有「忘记密码」流程**：目前只能通过 Supabase 后台重置。
- **暂无强制下线**：被限制的账户立即失去写权限，但已登录的会话不会被踢出。
- **文献文件只记录文件名与大小**，不会上传内容；下载为模拟进度。
- **备战夹并发**：同一数据标题的论据选择以最后一次保存为准，不做合并。
- **免费版 Supabase** 在一段时间无人访问后可能被暂停，上线前请查阅其当前政策与额度。
- 引用资料前请自行核验出处。
