# 国库 · DEBATE VAULT

> 为辩论选手打造的论据资料库：检索、核验、备战，一键导出 Word 备战稿。

![HTML](https://img.shields.io/badge/HTML-single%20file-e34c26) ![JavaScript](https://img.shields.io/badge/JavaScript-vanilla-f7df1e) ![Dependencies](https://img.shields.io/badge/dependencies-none-brightgreen) ![Storage](https://img.shields.io/badge/storage-LocalStorage-blue) ![Status](https://img.shields.io/badge/status-demo-orange)

**国库**是一个纯前端、单文件的辩论论据管理应用。资料按「数据标题」（辩题方向）分组，每条论据都带有领域、形式、年份、来源与出处凭证，并支持版本历史、真实性上诉与官方核验。选好论据放进「备战夹」，即可按固定版式导出为 Word 文档。

无需构建，无需服务器，打开 `index.html` 即可使用。

## 功能亮点

| 模块 | 说明 |
|---|---|
| 📚 **数据大厅** | 按数据标题分组的可折叠列表；22 个核心领域与 10 种资料形式侧栏筛选；全文搜索（含模糊匹配与关键词高亮）；组内按录入时间、论据日期或点赞数排序 |
| 🎒 **备战夹** | 为每场比赛建立备战辩题，从大厅一键收藏数据标题，再逐条勾选要用的论据；只引用不复制，不改动原资料 |
| 📄 **Word 导出** | 按固定表格版式（数据标题 / 出處 / 內容 / 參考）导出备战夹，网址自动生成超链接 |
| 📅 **论据日期** | 年份必填，月份与日期选填，显示与排序均按实际精度处理 |
| 🕰️ **版本历史** | 每次修正生成新版本，不可删除，时间轴可查 |
| ⚖️ **上诉仲裁** | 对存疑论据发起上诉，管理员仲裁；同一资料 24 小时内上诉与撤回各限 3 次 |
| ✅ **官方核验** | 管理员可标记「官方已核实」；管理员亦可下架资料 |
| 🎨 **外观** | 明暗模式、6 套低饱和配色、6 种强调色、减少动效选项 |
| ♿ **可访问性** | 键盘可达、`aria` 状态标注、弹窗焦点管理、尊重 `prefers-reduced-motion` |
| 📱 **响应式** | 900px 以下侧栏转抽屉，适配刘海屏安全区 |

## 快速开始

### 本地使用

```bash
git clone <your-repo-url>
cd <repo>
# 直接用浏览器打开
open index.html          # macOS
xdg-open index.html      # Linux
start index.html         # Windows
```

### 部署到 GitHub Pages

1. 将 `index.html` 放在仓库根目录并推送。
2. 进入 **Settings → Pages**，Source 选择 `main` 分支的根目录。
3. 几分钟后即可通过 `https://<user>.github.io/<repo>/` 访问。

### 首次使用

1. 打开页面，右上角 **设置 → 注册新账户**（默认身份为普通会员）。
2. 在设置的「切换模式」中输入授权密钥即可提权，密钥定义在源码的 `KEYS` 常量中，请在正式使用前自行修改。
3. 页面内置 8 个辩题、15 条示例论据，可随时在设置中重置。

> 快捷键：`/` 聚焦搜索，`Esc` 关闭弹窗、菜单或侧栏。

| 角色 | 权限 |
|---|---|
| 游客 | 检索、浏览 |
| 普通会员 | 游客权限 + 点赞 / 点踩 |

## 备战夹

备战夹相当于「按比赛分类的收藏夹」，仅授权贡献者及以上可用。

1. **选定战场**：在备战夹页面新建备战辩题（可同时备战多个），可随时「结束备战」或「恢复备战」。
2. **大厅收藏**：每个数据标题右侧有「备战」按钮。
   - 只有一个备战中的辩题：点击加入，再点一次取消，页面不跳转。
   - 有两个及以上：弹出多选框，可同时加入多个备战夹，取消勾选即移除。
3. **精选论据**：回到备战夹页面，勾选每个数据标题下要用的论据，点击「保存修改」生效；未保存的修改会有标记，可「放弃修改」。

设计原则：备战夹只保存对资料的引用，**不会修改数据大厅或数据库中的原始资料**；已下架的论据不会出现在备战夹，也不会被导出。

## Word 导出

在备战夹中选中辩题，点击「导出 Word」，生成 `备战夹_辩题名.docx`。

**版式**

- 每个数据标题一张单列带边框表格，首行居中加粗 18 磅显示标题。
- 每条论据一行，依次为：
  - `出處：来源名（日期）`，加粗，日期随填写精度显示为「2024 年」「2024 年 3 月」或「2024 年 3 月 5 日」
  - 论据内容，圆点列表
  - `參考：` 后接可点击的网址超链接；文献文件则写明文件名
- 纸张为 Letter，页边距 2.54 厘米。

导出在浏览器内完成：内置最小化的 `.docx` 与 ZIP 生成器，**不依赖任何第三方库**，可离线使用。

## 数据模型

所有数据存储在浏览器 LocalStorage：

| 键 | 内容 |
|---|---|
| `dv_db` | 资料库：`entries`（论据）、`log`（上诉熔断记录）、`court`（仲裁记录） |
| `dv_war` | 备战夹：`motions`（备战辩题，每个含 `items`：数据标题 → 论据 id 列表） |
| `dv_users` / `dv_session` | 本地账户与当前登录 |
| `dv_prefs` | 外观偏好 |

**论据（entry）主要字段**

```jsonc
{
  "id": "…",
  "topic": "数据标题",
  "content": "论据内容",
  "domain": "核心领域",
  "form": "资料形式",
  "year": 2024, "month": 3, "day": 5,     // month / day 可为 null
  "srcName": "来源名称",
  "src": { "t": "url", "v": "https://…" },  // 或 { "t": "file", "v": "文件名", "size": "2.1 MB" }
  "author": "录入者", "ts": 1700000000000,
  "up": [], "down": [], "verified": false, "offline": false,
  "versions": [ /* 不可删除的版本历史 */ ],
  "appeals": [ /* 上诉记录 */ ]
}
```

管理员可在设置中以 JSON 导出 / 导入全部资料、仲裁记录与备战夹。旧版领域与形式名称会通过 `DMAP` / `FMAP` 自动合并，导入旧数据不会错乱。

## 技术实现

- **纯前端单文件**：HTML + CSS + 原生 JavaScript（ES5 风格），无构建、无框架、无运行时依赖。
- **渲染方式**：状态集中在 `DB`、`USERS`、`WAR`、`session`、`P`（偏好）、`ui`（界面状态）；操作后保存并重渲染，所有点击经 `document` 上的 `data-act` 事件委托分发。
- **主题系统**：基于 HSL 变量（`--h` / `--s` / `--ha` / `--as`）生成整套配色，明暗两套，配色统一降饱和。
- **动效**：FLIP 排序动画、交错入场、滚动揭示、点赞粒子、按钮涟漪、主题切换圆形揭示（View Transitions API，不支持时自动降级）。
- **字体**：通过 Google Fonts 加载 Chakra Petch、JetBrains Mono、Noto Sans SC；离线时回退到系统字体。
- **浏览器**：现代桌面与移动浏览器（需支持 `crypto.subtle`、`color-mix()`、CSS `:focus-visible`）。

## 已知限制

这是一个**演示级**项目，请在使用前了解：

- **数据仅保存在本地浏览器**：不同设备、不同浏览器之间不会同步。「全员共享备战夹」目前只在同一浏览器的多个标签页之间同步。
- **权限不是真正的安全控制**：授权密钥写在前端源码中，任何人都能看到；密码仅做加盐 SHA-256 后存于本地。请勿用于需要真实访问控制的场景。
- **上诉熔断可被绕过**：限制记录在本地，清除 LocalStorage 即可重置。
- **文献文件只记录文件名与大小**，不会上传内容；下载为模拟进度。
- 内置示例数据仅供演示，引用前请自行核验出处。
